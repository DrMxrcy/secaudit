# Plan 44: Add kubernetes-security skill or docker-security section: Helm values secrets, RBAC wildcards, securityContext, hostPath, NetworkPolicy
> Type: feature · Target: v3.9.0

## 🎯 Target Scope & Boundaries
- **Core objective:** new `skills/kubernetes-security/` for apps that ship Helm charts or raw manifests (often generated by AI for k3s/homelab): secrets in `values.yaml` and ConfigMaps, `Secret` objects committed in plaintext (use external secrets / sealed secrets), RBAC wildcards (`*` verbs/resources, cluster-admin bindings, default ServiceAccount token automount), pod `securityContext` (runAsNonRoot, drop ALL caps, readOnlyRootFilesystem, seccomp RuntimeDefault, no `privileged`/`hostPID`/`hostNetwork`/`hostPath`), Pod Security Admission labels, NetworkPolicy default-deny, image tags vs digests and pull policy, exposed dashboards/NodePorts, resource limits as DoS control, in-cluster apps talking to the API server with over-scoped SAs.
- **Out of scope:** cluster bootstrap (Talos/kubeadm), service mesh, cloud-provider IAM.
